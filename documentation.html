Problem Statement

The original JKUAT Student Portal suffers from significant usability and interaction design issues that hinder student productivity and user satisfaction. This section outlines the core problems identified through HCI research and analysis.

Current System Challenges

Poor Usability

  • Complex, maze-like navigation structure
  • Overloaded interfaces with excessive information
  • Inconsistent layouts across different sections
  • Difficult discoverability of key features

Impact on Users

  • Increased task completion time
  • User frustration and dissatisfaction
  • High error rates during navigation
  • Poor system adoption among students

Inefficient Interaction Design

  • Too many steps required for basic tasks
  • No feedback after user actions
  • High cognitive load on users
  • Unclear system state and status

Impact on Users

  • Users unsure if actions succeeded
  • Repeated attempts at same tasks
  • Reduced user confidence
  • Abandoned workflows

Research Findings

Through HCI analysis, we identified that the system was designed primarily around administrative workflows rather than actual student needs. Key findings include:

  • User-centric gaps: System designed around administration, not students
  • Accessibility issues: Poor readability, limited device adaptability
  • Low learnability: New users struggle without extensive guidance
  • No user research: Student workflows treated as secondary

HCI Design Principles Applied

The redesigned JKUAT Student Portal is built on five core HCI principles. Each principle directly addresses the problems identified in the current system.

1. Usability & Visibility (Nielsen's Heuristics)

Principle: Visibility of System Status and Consistency

Problem
  • Complex navigation
  • Overloaded interfaces
  • Inconsistent layouts
Solution
  • Simplified navigation with clear hierarchy
  • Streamlined interfaces
  • Consistent design patterns

"Keep users informed about what's happening, and speak their language."

2. Interaction Design (Fitts's Law)

Principle: Optimal target sizing and task flow efficiency

Problem
  • Too many task steps
  • No action feedback
  • High cognitive load
Solution
  • Reduced task steps to minimum
  • Immediate visual feedback
  • Progressive disclosure

"Make frequently used actions quick and easy to perform."

3. User-Centered Design (ISO 9241-210)

Principle: Human-centered design process throughout lifecycle

Problem
  • Admin-first design
  • Secondary student workflows
  • No usage scenarios
Solution
  • User personas from research
  • Student-first workflows
  • Real-world scenarios

"Design for the user, not for the organization."

4. Accessibility (WCAG 2.1 AA)

Principle: Universal design for all users regardless of ability

Problem
  • Poor text contrast
  • Limited responsiveness
  • No assistive tech support
Solution
  • WCAG AA compliance
  • Fully responsive design
  • Screen reader optimized

"Design inclusively. What works for people with disabilities works for everyone."

5. Learnability (Cognitive Load Theory)

Principle: Intuitive design that minimizes learning curve

Problem
  • No user guidance
  • Unfamiliar patterns
  • Steep learning curve
Solution
  • Familiar interaction patterns
  • Contextual help & tooltips
  • Productive from day one

"Keep it simple. Reduce cognitive load through familiar design patterns."

System Design & Architecture

Portal Features

The redesigned JKUAT Student Portal includes 10 core features designed around actual student workflows:

📊 Dashboard

GPA overview, fee balance, today's classes, announcements

📅 Timetable

Weekly schedule with day filtering, course details

📚 Unit Registration

Browse, add, remove courses dynamically

📈 Results

View grades, automatic GPA calculation

📖 Library

Book borrowing, search functionality

🎓 E-Learning

Course materials, assignments, resources

👤 Profile

Edit user information, manage preferences

💬 Messages

Internal messaging system, inbox

🔔 Notifications

System alerts, updates, announcements

Technical Architecture

Stack Components

  • Frontend: HTML5, CSS3, Vanilla JavaScript (ES6+)
  • Storage: sessionStorage (temporary, per-session data)
  • Design Pattern: Single Page Application (SPA)
  • Responsiveness: Mobile-first, fully responsive design
  • No Dependencies: Pure vanilla technology, no frameworks needed

Design System

The portal follows a clean, modern design system with two theme options:

  • Light Theme: Clean, minimal, professional (default)
  • Dark Theme: Navy/dark gray with cyan accents (alternative)

Both themes maintain WCAG 2.1 AA color contrast compliance and support all device sizes.

HCI Principle Verification

✓ Visibility of System Status

Users always know the current state through clear headers, tab indicators, and real-time feedback on all actions.

✓ Match System & Real World

System uses student terminology and real academic workflows (registration, timetables, grades, fees) matching actual university operations.

✓ User Control & Freedom

Emergency exits always visible (logout buttons accessible, no modal traps), users can undo actions (remove registered units, return borrowed books).

✓ Error Prevention & Recovery

Input validation prevents invalid entries, confirmation dialogs for destructive actions, clear error messages guide correction.

✓ Aesthetic & Minimalist Design

Clean interface free of unnecessary elements, focus on student-relevant features, consistent visual design throughout.
